# Техническое задание: учебная социальная сеть

## Цель

С нуля создать учебную социальную сеть и понимать каждую самостоятельно написанную часть backend-кода. Нейросеть выступает наставником: объясняет, проверяет и помогает с интерфейсом, но не подменяет обучение.

## Обязательный стек

- Клиент: Next.js + TypeScript.
- Интерфейс: shadcn/ui как основа готовых компонентов, с собственным визуальным стилем.
- Сервер: Express.js + TypeScript.
- База данных: PostgreSQL.
- Кэш: Redis — подключается после рабочего MVP.
- Хеширование паролей и токенов: Argon2.

## Функциональность MVP

### Пользователь и профиль

- Регистрация и вход.
- У пользователя есть аватар, отображаемое имя и уникальный `username`.
- Пользователь может редактировать только свой профиль.
- Публичная страница профиля показывает пользователя и его посты.

### Авторизация

- JWT не используется.
- Авторизация построена на серверных opaque-токенах: токен — длинная случайная строка без данных о пользователе.
- После успешного входа сервер создаёт новую сессию и передаёт исходный токен браузеру в защищённой `HttpOnly` cookie.
- В БД хранится только хеш токена и связь с пользователем, а не исходный токен.
- Каждое устройство/вход создаёт отдельную сессию.
- Сессию можно отозвать отдельно; после отзыва её токен больше не даёт доступ.
- Сессия хранит как минимум: пользователя, хеш токена, дату создания, срок действия, IP-адрес, user-agent, сведения о браузере/устройстве и состояние отзыва.
- Active sessions are a required security screen: each login/session must be separately revocable. This is **not** a general settings section.

### Контент

- Общая лента постов без рекомендаций.
- Создание постов авторизованными пользователями.
- Лайки постов.
- Комментарии к постам.
- Пользователь может редактировать или удалять только собственные посты и комментарии.
- При удалении поста удаляются связанные лайки и комментарии.

## Порядок работы

1. Согласовать простой макет и структуру экранов.
2. Собрать frontend-каркас и UI на shadcn/ui.
3. Поднять Express и PostgreSQL.
4. Спроектировать таблицы и связи.
5. Реализовать регистрацию, вход и серверные сессии.
6. Реализовать профиль и редактирование профиля.
7. Реализовать посты, ленту, лайки и комментарии.
8. Подключить Redis как отдельный этап после MVP.

## Ближайший результат

В ближайшую неделю готово: регистрация, авторизация через серверные сессии, профиль с аватаром/именем/уникальным username и редактирование собственного профиля.

## Учебные правила

- Перед новым блоком: короткое объяснение его цели и терминов.
- Код пишет Владислав и понимает назначение каждой строки.
- Наставник проверяет код, помогает найти ошибку и объясняет причины.
- UI можно собирать при активной помощи нейросети, но его устройство также разбирается.
