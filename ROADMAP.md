> Правило: не перескакиваем через блок. Новый блок начинается только после понятного результата предыдущего.

## Границы MVP

**В MVP есть:** регистрация, вход, серверные сессии с отдельным отзывом, профиль, редактирование своего профиля, текстовые посты, общая лента, лайки и комментарии.

**После MVP:** Redis, изображения, ссылки и вложения в постах, теги, поиск, рекомендации, уведомления, подписки, друзья, личные сообщения, real-time.

## Блок 4. Регистрация, вход и серверные сессии

**Цель:** сделать ядро безопасности приложения.

### Последовательность

1. `POST /auth/register`: валидация, уникальные username/email, Argon2-хеш пароля, создание User.
2. `POST /auth/login`: поиск User, проверка Argon2, создание случайного raw token.
3. Сохранить в БД `hash(token)`, userId, даты, IP, user-agent и состояние сессии.
4. Отдать raw token только в HttpOnly cookie.
5. Auth middleware: cookie → hash token → активная Session → `req.user`.
6. `POST /auth/logout`: отозвать текущую сессию.

**Контрольная точка:** после логина защищённый endpoint понимает, какой пользователь сделал запрос; после logout старый токен не работает.

## Блок 6. Контент

**Цель:** сделать собственно социальную сеть.

### Посты и лента

- [ ] Создать, прочитать, изменить и удалить текстовый пост.
- [ ] Менять/удалять можно только собственный пост.
- [ ] Общая лента: новые сверху.
- [ ] Pagination: `page` + `limit`.

### Лайки и комментарии

- [ ] Один пользователь может поставить один лайк одному посту: `UNIQUE(userId, postId)` в БД.
- [ ] Создать комментарий может авторизованный пользователь.
- [ ] Удалить комментарий может только автор.

**Контрольная точка:** backend не доверяет кнопкам frontend: запрос на удаление чужого поста даёт `403`.
